# Blockfall

A falling-blocks puzzle for the browser: stack the pieces, clear lines, and in a duel send the lines you clear to your opponent.
Play **solo** (marathon: the level rises with your lines), **against the computer** (three levels), or **online** against another
player (lobby, quick match, challenges, Elo leaderboard). French and English, keyboard and touch (phones included).

## Features

- Ten columns by twenty rows, the seven pieces drawn from shuffled bags, super rotation system with wall kicks, ghost piece, hold,
  five pieces of preview, soft drop, hard drop, lock delay, automatic repeat of moves (DAS / ARR), levels with gravity that speeds up.
- **Duel**: clearing lines sends garbage lines to the opponent (single 0, double 1, triple 2, four 4, +1 for a back-to-back four,
  plus a combo bonus); your own clears first cancel the garbage you were about to receive. The speed rises with time, so a duel always ends.
- **Against the computer**: it looks at every position it can reach (moves and wall-kick rotations from the spawn), scores them
  (height, holes, bumpiness, lines) and plays the best one key by key. Easy is slow and often misplaces a piece, normal uses the hold
  box, hard also looks one piece ahead and plays about two pieces per second.
- **Online multiplayer**: a central PHP 8.5 server runs both boards at 60 images per second with the same engine as the browser;
  the browsers only send their keys and receive what changed. Three-second countdown, rematch, ping display.
- **Ranked matches** with an Elo rating, without any account: each browser has a secret token (only its SHA-256 hash is stored)
  that reserves the nickname. Anti-collusion: gains shrink when the same two players meet again within 24 hours.
- **Phones**: no buttons, gestures on the whole play area. Swipe left or right to move the piece one cell per cell your finger
  travels, swipe up or tap to rotate, swipe down to drop it at once, long press to hold. The board takes the width in portrait (the
  opponent's board is a small one at the top) and the full height in landscape; fullscreen with landscape lock on Android, screen
  kept awake, notches and home bar respected.
- Sounds are synthesized (no audio files); the solo and computer modes work offline.

## Quick start

```bash
git clone <this repository> blockfall
cd blockfall
docker compose up -d --build
```

Game: <http://localhost:8095> — game server: `ws://localhost:8096`. See [INSTALL.md](INSTALL.md) for a setup without Docker,
the configuration variables and a reverse-proxy example.

## Controls

| | Keyboard | Phone |
| --- | --- | --- |
| Move | ← → or **A D** (**Q** on AZERTY) | swipe left / right (one cell per cell travelled) |
| Soft drop | ↓ or **S** | — |
| Rotate | ↑, **X** or **W** (clockwise), **Z** or Ctrl (counter-clockwise) | swipe up, or tap |
| Hard drop | **Space** | swipe down |
| Hold | **C**, **H** or Shift | long press |
| Pause | **Esc** or **P** | ⏸ |

## Architecture

```
web/                 the website, served by Apache (document root)
  index.php          single page (menu, lobby, game); injects the WebSocket URL (BLOCKFALL_WS)
  js/engine.js       the game: board, pieces, rotations, gravity, scoring, garbage, duel (pure, integers only)
  js/ai.js           the computer opponent (seeded random generator: a game is replayable)
  js/render.js       canvas rendering: board, ghost, hold, next, garbage gauge, effects; wide and tall layouts
  js/input.js        keyboard and touch-gesture controller (held keys, actions, taps shorter than a frame still count)
  js/main.js         menus, game loop at 60 Hz, solo / computer / online modes, lobby
  js/net.js          WebSocket client       js/audio.js  synthesized sounds       js/i18n.js  FR / EN
  api.php            leaderboard (GET), reads the file written by the game server
src/                 all PHP code, PSR-4 namespace `Blockfall\` (see below)
server/              entry point of the game server (a few lines of wiring), outside the web root
tests/               JS unit tests, PHP unit tests, integration tests, browser tests (desktop and phones)
```

### The engine exists twice, and tests keep both identical

The browser needs the engine for solo and for the computer; the server needs it to referee online duels. `web/js/engine.js` and
`src/Engine/` are two implementations of the same rules, and everything in them is an integer (gravity is in 1/65536 of a row per
frame, the random numbers come from an integer xorshift generator), so they must agree exactly, frame by frame.
`tests/fixtures/engine-vectors.json` (generated by `npm run fixtures`) records games played by the JavaScript engine — the computer
at all levels and random inputs, solo and in duels, with every key press — and `tests/php/Engine/FixturesTest.php` replays them with
the PHP engine and compares the full state of every board every 120 frames (grid, piece, queue, hold, score, lines, level, pending
garbage, alive).

### PHP code (`src/`)

PHP 8.5, PSR-4 autoloading, PSR-12 style, `declare(strict_types=1)` everywhere, PHPStan level 8. Runtime dependencies are the PSR
interfaces `psr/log` (PSR-3) and `psr/clock` (PSR-20), and [`openprunus/arcade-core`](https://github.com/OpenPrunus/arcade-core),
the WebSocket server and support classes shared with the other games (namespace `Arcade\`).

| Namespace | Role | Patterns |
| --- | --- | --- |
| `Blockfall\Engine` | The game: `Board`, `Versus`, `Shapes`, `Piece`, `Input`, `Action`, `GameEvent`, `Rules` | Value objects, enums |
| `Blockfall\Game` | The multiplayer server: `GameHub` (facade), `Lobby`, `Invitations`, `MatchQueue`, `MatchService`, `Room`, `RankingBook` | **Command** (one `Handler\*` per client message), **Factory** (`GameHub::create`), **State** (`RoomPhase`) |
| `Blockfall\Ranking` | `Elo`, `Ranking` (immutable), `Player`, `PairLimiter`, `RankingStore` | **Repository** (`RankingStore`), immutable objects updated with `clone with` |
| `Blockfall\Api` | `Board`: the public leaderboard | |
| `Arcade\WebSocket`, `Arcade\Server`, `Arcade\Support` *(arcade-core)* | RFC 6455 codec, the `stream_select` server, helpers | **Adapter** (`Connection` implements `Transport`); the game plugs in through `Hub` and `Session` |

### How online play works

- The browser opens a WebSocket, sends `hello` (nickname + token) and joins the lobby. `queue` starts a quick match, `challenge`
  invites a player. The server tosses a seed and sends `match`, then a countdown (`cd`) and `go`.
- During the game the browser sends `keys` (left, right, soft drop held — only when they change) and `act` (`left`, `right`: one
  cell; `cw`, `ccw`, `hd`, `hold`). The server steps both boards at 60 Hz and sends `s` with only what changed on each board, plus events (lock, clear,
  garbage, attack) for the effects. The loser is the first whose next piece has no room; then `result`.
- Keys are never trusted for anything but moving your own piece: no score, no board and no garbage ever comes from a client.
  Origin check on the WebSocket, 120 messages per second per client, 2 KB per message.

## Tests

```bash
composer install && composer check   # PSR-12, PHPStan level 8, PHPUnit (incl. replay of the JS engine's games)
npm run test:unit         # engine, computer, translations
npm run test:integration  # the real PHP server on a real port, WebSocket clients
npm run test:browser      # headless Chrome: menus, keys, pause, solo, computer duel, phones (portrait and landscape), online match
```

CI runs all of it and a smoke test of the Docker image on every push.
